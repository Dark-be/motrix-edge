# robot-pipeline 重力补偿与阻抗控制

> **状态**：**阶段 0/1 已实现、阶段 2 已接通（默认占位、行为不变）**（分支 `feat/impedance-control`）：
> 标定工具、回归器 / 拟合与控制器侧前馈注入都在仓库里；参数未标定前指向**占位文件（全 0）**，
> `t_ff` 恒为 0，与未补偿完全一致。阶段 3–5（笛卡尔 K/D / 导纳 / 力矩型）未实现。

## 摘要

机器人侧的位姿控制目前**只有位置环**：MIT 的 `t_ff` 恒为 0（`MIT_CTRL_CFG` 的 `t_ref = 0`），
不补重力，于是每个受重力的关节都停在 `τ_g / k_p` 附近的平衡点——**设定什么关节角就是什么
关节角这件事并不成立**（见 [位姿动作](./robot_pipeline_cartesian.md)）。现场为此把「到位」容差
放宽到 5 cm / 0.4 rad 来吸收它。

本文给出两条正交的能力：**重力前馈**（解决精度）与**阻抗塑形**（解决接触时怎么让开）。核心
判断是——**两者都不需要动力学模型、URDF 或六维力传感器**：

-   **重力项只对「质量 + 一阶质量矩」线性**（每连杆 4 个参数，惯量张量根本不进重力项），所以
    用电机侧力矩读数做一次离线标定就能拿到 `τ̂_g(q)`，前馈进 MIT 的 `t_ff`；
-   **柔顺**可以先由「笛卡尔 K/D 折回关节增益 `Jᵀ K_c J`」实现（只要雅可比，现成），需要更强的
    让步行为时再叠「位置型导纳」（`τ_ext = τ_meas − τ̂_g` → 修正目标位姿）。

据此**不引入 Pinocchio**：它只有在要做完整动力学（`M(q)` / 科氏）或力矩型阻抗时才需要，而那时
必须先有可信的惯量参数（URDF/CAD）——见「未决项」。

## 目标与成功标准

**问题**：位姿 / 关节目标会因重力塌陷，导致（a）到位判定要靠放宽容差，（b）想做低刚度柔顺时
塌陷大到不可用（`τ_g / k_p`，肩肘可达 1 rad 量级）。

**目标**：在**不新增硬件、不引入动力学模型**的前提下，把重力从控制回路里补偿掉，并给出可设计
的柔顺行为。

**成功标准**（都可量化验收）：

1. 同一批标定位形上，`k_p · |q_des − q_ss|` 从未补偿的 `τ_g` 量级降到**摩擦量级**（`k_p=4`
   时约 1.4–7°）；
2. 前馈不改变**位置环的稳定性**（无自激、无极限环）；
3. 异常（读数失败 / 超时 / NaN / 超限幅）时**立即退回纯位置环**（`t_ff = 0`），机器人不动坏；
4. 柔顺：人手推末端时按设计的 `K_c` / `D_c` 让开，且不与重力补偿互相干扰。

## 整体原则

1. **前馈，不回灌**：`t_ff = τ̂_g(q_meas)`——重力只是关节角的函数，与外力无关。**绝不**把实测
   力矩即时回灌成 `t_ff`：那在稳态下等价于把 `k_p` 放大到无穷（外力一推就顶回等大的力），
   **柔顺性直接消失**，还会把读数噪声原样灌进力矩指令。
2. **只辨识需要的量**：重力项的参数集是每连杆「`m`、`m·c`」4 个（见下节推导），
   **不用惯量张量、不用 URDF**；`m` / `c` 的物理真值不必已知——最小二乘给出的系数只要
   在采样域内能重现力矩即可（超出采样域的外推才是风险）。
3. **单一模型**：回归器 `Y(q)` 由 `PIPER_DH` 推出，与 FK / IK / 限幅共用同一份运动学
   （见 [位姿动作](./robot_pipeline_cartesian.md) 的「限位只有一份」口径）；**不引入第二个模型
   文件**（URDF）。
4. **分阶段落地，每阶段独立可验收**：重力前馈 → 笛卡尔 K/D 折回关节增益 → 位置型导纳 →
   （远期）力矩型阻抗。前一阶段是后一阶段的前提，但都各自能单独上线。

## 可用信号与量程（单点定义）

| 信号                                   | 来源                                                                                           | 用途                                                          |
| -------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| MIT 力矩律                             | SDK `move_mit`：`T_ref = k_p (p_des − p) + k_d (v_des − v) + t_ff`                             | 前馈的注入点；`p` / `v` 是**实测**值                          |
| 关节角 / 速度 / 电流 / **力矩**        | SDK `get_motor_states(i).msg.{position, velocity, current, torque}`（rad、rad/s、A、**N·m**）  | 力矩读数是本文一切辨识与力估计的基础（**按关节取，1-based**） |
| `t_ff` 量程                            | 固件 V188：**12-bit，全关节 ±16 N·m**（旧版驱动为 1–3 轴 ±32 / 4–6 轴 ±8）                     | 前馈限幅的硬边界                                              |
| `k_p` / `k_d` / `p_des` / `v_des` 量程 | SDK：`k_p ∈ [0, 500]`、`k_d ∈ [−5, 5]`、`p_des ∈ [−12.5, 12.5]` rad、`v_des ∈ [−45, 45]` rad/s | 阻抗塑形（K/D 折回关节增益）的可行域                          |
| 六维力 / 力矩传感器                    | **无**                                                                                         | 力只能从 `τ_ext = τ_meas − τ̂_g` 折算（见「能力边界」）        |

`move_mit` 是**直通、无平滑**模式（SDK 原话：_the lower layer only forwards messages with no
smoothing_）——所以「悬停」「保持前馈」都要求**每拍重发**，不能设一次就完。

## 为什么重力项只需要少量参数

重力广义力是 `τ_g,j = Σ_i m_i · gᵀ · ∂p_i^c/∂q_j`，其中连杆 i 的质心位置
`p_i^c(q) = o_i(q) + R_i(q)·c_i`（`o_i` / `R_i` 由 DH 给出）。展开后：

> 重力项对参数 **`π_i = (m_i, m_i·c_i) ∈ ℝ⁴`** 线性——即「质量 + 一阶质量矩」，
> **每连杆 4 个**；惯量张量 `I_i` 只出现在动能里（`M(q)` / 科氏），**不进重力项**。

6 连杆最多 24 个参数，扣掉不可辨识的子集（只影响绕竖直轴的、静态位形下不可观测的）通常落在
**8–14 个**。这就是「不装 Pinocchio 也能做重力补偿」的定量理由：写成

$$\hat\tau_g(q) = Y(q)\,\hat\pi,\qquad Y(q)\in\mathbb{R}^{6\times n_\pi}$$

`Y(q)` 纯 numpy 可得（DH 正解 + 解析/数值求导），运行期只做一次小矩阵乘法。

## 标定流程（离线，不影响运行）

工具：`robot-pipeline/scripts/verify_gravity.py`（现场取数，默认**只读**）+
`robot-pipeline/scripts/fit_gravity.py`（离线拟合，**不碰硬件**）。分五步：

1. **自检（`--read`）**：只读 N 秒，报告每位关节的 `q` / `velocity` / `torque` 均值与标准差、
   单次读取耗时。产出：读数是否可用、噪声量级、**读数开销**（`get_motor_states` 是按关节
   请求/应答，6 次/拍的事实必须实测）。
2. **符号 / 单位自检（`--hold`）**：以**当前实测位置**为目标持续下发（不会移动），等稳后逐关节
   比对 `τ_meas` 与 `k_p·(q_des − q_meas)`。二者一致（同号、幅值同量级）才说明读数与下发同号
   同单位——**这一步不做就不能上前馈**（方向错等于主动推机器人）。
3. **采样（`--sweep`）**：从基准位形扫一批位形，正反两遍，落盘原始样本 JSON：
    - **悬停靠位置环本身**：以 30 Hz 持续重发同一目标，臂自动停在 `q_ss = q_des − τ_g(q_ss)/k_p`；
      采样配对的是「**实测 `q`** + 实测 `τ`」——**稳态点不是指令点**，这正是要量的东西；
    - **判稳**：连续 K 拍满足 `|velocity| < εv`、`|Δτ| < ετ`、`|Δq| < εq`，再取窗口均值与
      标准差；标准差超阈值（有碰 / 振 / 粘滑）→ 丢弃该点并记原因；
    - **正反两遍**：同一实测 `q` 邻域从两个方向各采一次，`τ_g ≈ (τ⁺ + τ⁻)/2`，方向相关的
      库仑摩擦自动抵消，同时得到摩擦幅值的估计；
    - **激励质量**：位形按关节行程分布（`Y(q)` 条件数在拟合阶段评估）；点位必须由限位过滤，
      越界的一个都不发。
4. **拟合与验证**：`fit_gravity.py` 最小二乘解 `π̂`（可选岭正则 `--ridge`），并回代到采样位形给出
   残差 RMS / 最大、秩、条件数与「残差最大的几个位形」（被碰 / 未停稳的点看这里）+ 样本内
   `|τ̂_g|max`（是否会被固件削顶）。产物是 `π̂`（6×4 个数）+ 元信息（DH、负载、报告），
   而不是一张大表。
    - 秩通常**低于 24**（关节 1 的轴竖直、重力不产生绕它的力矩等结构不可辨识方向）：本仓 Piper 的
      实测合成数据上是 **10/24**——最小二乘给的是**最小范数解**，采样域内力矩仍被精确重现，但
      **参数值不是物理质量**（故产物与日志都不报「质量合计」），域外推才是风险。

**不能用固件的拖拽示教模式（drag teach）代替标定**：那个模式下固件自己在做重力补偿，
电机力矩读数 ≈ 0，采不到 `τ_g`；且它与 MIT 直通互斥。

## 运行时接入（已实现）

-   **注入点**：`PiperController`。`set_joint()` 里若**显式**传了 `torque_ff` 就照传（留给后续导纳 /
    手动试验的口子）；否则当 `robot.gravity` 装载过模型时，每拍读**实测 `q`**（`get_motor_states()`，
    读的是 SDK 后台线程已解析的缓存帧，非请求 / 应答）并下发 `α·τ̂_g(q_meas)`。
    `move_mit` 是直通无平滑模式，所以每拍重发本身就要求读 + 算 + 发同一拍完成。
-   **配置**（机型 yml 的 `robot.gravity`，已写在 `single_piper.yml` / `dual_piper.yml` /
    `dual_alicia_piper.yml`；只装在**执行**臂上，主臂只读不装）：

    ```yaml
    robot:
        gravity:
            enabled: true # 缺省 true；参数未标定时指向占位文件（全 0）→ t_ff 恒为 0
            alpha: 1.0 # 前馈比例（0 = 不补偿）
            t_ff_limit: 16.0 # 单关节前馈上限（N·m）：固件硬限幅 ±16，只能收紧
            params: gravity/piper_6dof.json # 参数文件（相对配置目录；也可按臂给）
    ```

    路径解析与 yml 同一套优先级（外部 `MOTRIX_EDGE_CONFIG_DIR` 优先，否则包内兜底）；参数文件
    里记了 DH，**与当前运动学不一致就拒绝装载**（用另一套 DH 标定的参数会算错力矩）。

-   **每臂一份**：`params` 可写成 `{left: ..., right: ...}`，或用 `arms.<控制器名>.params` 覆盖
    （装配与现场误差不同，双臂不能共用一套）。
-   **限幅与降级**：`|τ_ff| ≤ min(16 N·m, 配置上限)`；读数失败 / 超时 / NaN / 参数域外 / 模型异常 →
    **本拍 `t_ff = 0`**（退回纯位置环）+ 告警一条（同一原因只打一条，30 Hz 不刷屏），控制不中断。
    占位参数（全 0）是**短路**：连读数都不取，零开销。
-   **可观测**：`PiperController.gravity_status()` 给出是否生效 / α / 限幅 / 占位、降级与限幅计数、
    当前原因、最近一拍 `t_ff`（`last_torque_ff` 也在控制器上）；健康检查接入 `/v1/health` 属后续小改。
-   **渐进上线**：`α` 从 0.2 起逐档提到 1.0，每档在同一姿态对比 `k_p·|q_des − q_ss|`——现场用
    `verify_gravity.py --hold --alpha <α>`（α=0 与 α=1 各跑一次，同一姿态可比）。

## 静态精度与柔顺的取舍（必须理解的一条）

稳态下代入力矩律：`Δq = [(τ_g − τ̂_g) + τ_fric + τ_dyn] / k_p`。于是：

-   **残余静差的主导项是摩擦**（0.1–0.5 N·m ⇒ `k_p=4` 时 1.4–7°），不是重力模型精度；
-   **`Δq` 与 `k_p` 成反比**：静差「小」可能是因为刚度「大」——**消除静差与柔顺是同一枚硬币的
    两面**。重力前馈的真正价值不是「更准」，而是**让 `k_p` 可以调低**（否则低刚度下 `τ_g/k_p`
    大到不可用）；
-   想把最后那几度也消掉，可叠一层**慢速积分**（吃掉摩擦与负载漂移）；前馈吃大头、积分吃残渣，
    但要注意与固件内环的稳定性（限幅、抗饱和）。
-   **动态误差不在此列**：`M(q)q̈ + C(q,q̇)q̇` 未补，改善的是**准静态**精度，跟随误差不变。

## 阻抗的形态与选型

「阻抗」= 设计「被外力推时应让开多少」：`M_d ẍ + D_d ẋ + K_d Δx = F_ext`。按所需模型排成一条谱：

| #   | 形态                                                                                                              | 需要的量                                  | 位置                                                                                                                          |
| --- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1   | **关节刚度 / 阻尼**（固件 `k_p` / `k_d` 本身就是）                                                                | 无                                        | 已有；只是固定、无法按笛卡尔方向指定                                                                                          |
| 2   | **笛卡尔 K/D 折回关节增益**：`K_q = Jᵀ K_c J`（`D_q` 同理）                                                       | 只要 `J`（**现成**）                      | **推荐的"真阻抗"第一步**：不碰 `t_ff`、不要动力学、全程留在固件安全网内；`J` 随构型变 → 每处目标重算，奇异性处需正则化 / 截断 |
| 3   | **位置型导纳（让步）**：`τ_ext = τ_meas − τ̂_g` → `F_ext ≈ J⁻ᵀ τ_ext` → 导纳积分 → 修正 `x_des` → IK → `set_joint` | `τ̂_g` + `J`                               | 无力传感器下能做**准静态**柔顺；带宽受 30 Hz 环 + 滤波限制                                                                    |
| 4   | **力矩型阻抗**：`τ = M ẍ_ref + C ẋ + τ̂_g + Jᵀ(K Δx + D Δẋ)`，`k_p → 0`                                            | `M(q)`、`C(q,q̇)` = **惯量** ⇒ URDF / 辨识 | 真柔顺、带宽高，但**失去固件位置安全网**，风险最高；见未决项（Pinocchio）                                                     |

**能力边界（写清以免误用）**：第 3 条的力信号来自 `τ_ext = τ_meas − τ̂_g`，其精度受摩擦与辨识
残差限制（约 0.1–0.5 N·m 量级）——够「人手推一下让开」（> 1–2 N·m），**不够精确测量小接触力**。

## 验收

1. **精度**：同一批标定位形，比较补偿前 / 后的 `q_des − q_ss`（等价于 `k_p·Δq`），应下降到摩擦
   量级；`α` 每档都要看这条。
2. **安全**：拔掉 / 遮挡读数、注入 NaN、超限幅 → 当拍 `t_ff = 0` 且不中断控制。
3. **柔顺（阶段 2/3）**：人手在末端沿某轴推，测量稳态位移与设计刚度 `K_c` 的一致性（同一构型
   下可比）。

### 数学正确性怎么保证（无自动化测试）

约定：**robot-pipeline 的用例不进 edge 的 `tests/`**（那里只测 `motrix_edge` 包），因此本轮不为
重力数学建自动化测试文件，而是把校验做成两个**可执行入口**（都在实现 / 工具里，不依赖 pytest）：

-   `python scripts/fit_gravity.py --self-test`：离线自检 7 项——回归器 = 势能 `∂U/∂q` 的**数值**
    偏导、法兰点质量 = `−J_vᵀ·m·g`（与 `PiperKinematics.jacobian` 独立对齐，含符号）、拟合重现
    合成样本（残差 RMS ~1e-15）、占位 / α 缩放 / 限幅 / 异常降级。**改 DH 或改重力数学后先跑它**。
-   `python scripts/verify_gravity.py --hold`：现场**符号 / 单位自检**——
    `τ_meas` 与 `k_p·(q_des − q_meas)` 必须同号同量级（读数与下发同一符号 / 单位），这一步不过就
    不能上前馈（方向错等于主动推机器人）。

阶段 2 的注入路径（`set_joint` → `move_mit(t_ff=...)`）本轮没有自动化测试（随硬件相关用例一起
从 edge 侧移除）；要补就补在 robot-pipeline 自己的测试位置（等测试归属约定定下来）。

## 未决项

1. **摩擦模型**：本次只做重力。是否补 `F_c·sign(q̇) + F_v·q̇` 取决于标定时测到的静摩擦幅值。
2. **负载在线估计**：换工件不重标是否可行（用 `τ_ext` 的稳态残差估计附加质量）。
3. **Pinocchio**：只在第 4 条（力矩型）才需要，且**前置条件**是拿到可信惯量（厂商 URDF/CAD 或
   完整辨识）。届时必须配一条「URDF ↔ `PIPER_DH` 一致性」测试（`fk()` 逐位对齐 +
   `scripts/verify_cartesian.py` 现场核对），否则就是两个事实来源。
4. **单臂 / 双臂**：每臂独立标定与归档；双臂是否要做「同型号共用初值 + 现场微调」。
5. **导纳带宽**：30 Hz 环 + 滤波能支撑多软的 `K_c`，需现场试验。
6. **`k_p` 折回后的量程**：`Jᵀ K_c J` 在近奇异位形会给出超出 `[0, 500]` 的增益 → 截断策略。
